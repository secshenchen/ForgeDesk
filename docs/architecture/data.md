# 数据层

批次 04 已实现 UTF-8 键值配置、日志与路径服务，详见 [基础服务](../development/services.md)。SQLite 和业务数据库仍在规划中。

## 数据类别

| 数据 | 规划管理方式 |
| --- | --- |
| 用户设置 | 批次 04 的 `SettingsStore`，第一阶段使用简单 UTF-8 键值文件 |
| 日志 | 批次 04 的 `Logger`，限制大小并轮换 |
| 结构化业务数据 | 后续 SQLite；模式和迁移源码放 `database/` |
| 缓存/临时文件 | 独立目录，明确所有权和清理范围，不自动删除用户文件 |
| 大型实验数据 | 独立可配置路径，允许其他磁盘，不提交 Git |

`database/` 是源码层的模式、迁移与说明预留位置，不是运行时数据库目录。SQLite 的版本、来源、许可证和离线部署在真正引入时登记，当前没有捆绑依赖。

## 路径与保存

应用数据、配置、缓存、日志、临时和实验数据目录由后续 `AppPaths` 管理。安装目录与用户数据严格分离，默认不写 Git 仓库；支持明确选择的自定义目录与便携模式，不硬编码 C 盘。权限不足、磁盘写满、非法配置和备份失败必须可诊断。

设置格式须在实现前规定注释、转义、重复键、类型、默认值和错误语义，不能用未经验证的复杂序列化格式。保存考虑备份、失败恢复和写入结果检查；加载失败不应默默覆盖原数据。

## 隐私与迁移

默认本地保存、不自动上传。日志不包含敏感内容，源码仓库不保存凭据、私人数据库或本地配置。浏览器持久化与 Windows 文件系统分别实现，说明配额、权限及清理行为，不承诺同等容量或耐久性。

未来数据库更改应记录模式版本、事务与迁移失败策略；破坏性迁移须评估备份和回退。测试使用隔离临时数据，覆盖无权限、损坏、重复键和保存恢复，不能操作原用户文件。
