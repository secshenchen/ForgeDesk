# 总体架构

状态：v0.1.0 批次 01 的设计基线；这里描述未来边界，没有宣称接口已经实现。

ForgeDesk 采用分层模块化架构，以共享 C++23 核心支持 Windows 桌面版与 Web 版。应用层完成装配，平台层提供受约束的能力，模块实现未来业务，界面展示状态和交互，持久化实现通过独立边界接入。

## 依赖与职责

```text
共用 ui（HTML / CSS / JavaScript）
             │ 明确消息协议或 Web 适配调用
             ▼
apps/windows 或 apps/web（启动、装配、权限接入）
             ├── modules ──► core
             ├── platform ─► core 中声明的接口
             └────────────► core
```

`core` 不依赖 `apps`、`modules`、`platform` 的实现或 UI。模块不直接操纵 DOM，不直接访问 WebView2；通过明确接口接入平台服务。`platform` 实现核心定义的接口，应用注入这些实现，不使用全局可变服务定位器。禁止任何循环依赖。

## 生命周期与错误

应用后续按“建立平台上下文 → 初始化基础服务 → 注册模块 → 展示 UI”启动。关闭时停止接受新任务、协作取消或等待运行任务、反向关闭已初始化模块、刷新并关闭基础服务。部分初始化失败只清理已成功获得的资源。

可恢复错误通过明确结果传递到应用层，再转换为可读 UI 信息；不能吞掉异常或用默认成功值掩盖错误。后台工作与界面线程通过受控通知边界通信，避免后台线程直接修改 UI。

## 本阶段范围

01 建文档与规范；02 建构建；03 建核心类型及静态模块系统；04 建基础服务；05 建离线 UI 和双平台基础；06 建自动化和发行准备。本批不实现上述运行时机制。十个业务中心不在第一阶段实现。

扩展新平台或模块时遵守既有边界，重大技术变化写 ADR，保持原生构建与离线能力。技术选择原因见 [ADR-0001](../decisions/ADR-0001-technology-stack.md)。
