# 平台层

批次 03 提供 `IPlatformServices`，批次 05 加入浏览器能力探测和 Windows 宿主适配。应用层后续按业务需求接入完整文件与诊断服务。

`platform/windows/` 与 `platform/web/` 实现核心所声明的抽象，应用层选择并注入。平台实现可以依赖核心，核心不能反向包含平台实现。未来 Linux 可新增独立目录，不修改核心算法来迁就操作系统。

## 计划平台服务

`IPlatformServices` 将描述当前平台、应用数据/配置/缓存/临时目录、平台能力和文件访问能力。能力至少覆盖 `FileSystem`、`SystemInformation`、`NetworkDiagnostics`、`Clipboard` 和 `NativeDialogs`。能力描述须区分“实现存在”“当前环境支持”“已获授权”，不能仅凭编译平台就认为调用必定成功。

Windows 目录由系统及用户设置解析，不写死盘符。文件操作要验证路径、覆盖语义、权限与 I/O 结果，不默认提权，不自动删除用户文件。安装目录只放程序和资源，用户数据另存；便携模式须明确启用。

## Web 平台

Web 适配层检测文件选择、下载、剪贴板、本地存储和受授权文件访问。支持性、安全上下文和权限应在实际使用时核实，用户拒绝或功能缺失须返回清晰错误。不能把文件选择器等价为任意磁盘访问，也不能将浏览器存储描述为 Windows 本地路径。

## 通信与权限

宿主通信由应用层负责：校验消息来源、操作白名单、参数、权限和返回值。平台能力声明只是模块需求描述，不能代替用户授权。不要向 JavaScript 暴露任意 shell 或无限制文件操作。

平台测试将覆盖不支持、权限拒绝、非法路径与服务失败；集成测试与纯核心测试分开，浏览器测试不能假冒原生 Windows 权限。平台支持矩阵见 [双平台关系](windows-web.md)。
