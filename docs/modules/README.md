# 模块开发约定

模块公共接口位于 `core/include/forgedesk/module.hpp`。本阶段使用静态注册，业务中心仍在规划中。

## 目录与依赖

未来模块放在 `modules/<module_name>/`，按需增加头文件、实现与测试，不为十个中心生成空类。模块可依赖核心，核心不依赖模块。模块不直接引用 WebView2 或 DOM，平台能力经应用注入服务获取，不允许循环依赖。

## 描述与注册

模块声明非空且唯一的 `ModuleId`、名称、版本、描述和能力集合。应用在同一所有者线程创建 `ModuleRegistry registry{platform}`，使用 `registry.register_module(std::make_unique<YourModule>(...))` 转移所有权，并处理结果。平台必须比注册表活得更久，模块回调不得重入注册表。

## 生命周期

注册表先读取 `descriptor()`，检查 ID 和能力，再调用 `initialize()`。成功后标记为 active。失败或初始化抛异常时调用 `shutdown()` 清理并移除条目。注销也调用 `shutdown()`，析构时按逆注册顺序关闭剩余模块。该方法须能清理部分初始化的资源，且不得抛出异常。`find()` 返回借用指针，注销后失效。`list()` 返回描述快照。

## 贡献验收

新增正式模块时同时提交能力与权限说明、错误协议、生命周期文档、测试和变更记录。覆盖正常注册、重复、查询、注销、初始化失败、关闭与能力不足。UI 只能报告真实模块状态，未实现中心显示“计划中”。详见 [贡献指南](../../CONTRIBUTING.md)。

## 未来插件扩展

动态插件不是第一阶段交付。未来必须先新增 ADR，明确 ABI/协议版本、来源信任、能力与授权、隔离、装载/卸载、失败恢复与更新兼容，再实现受控加载。不能把静态模块接口直接当成可安全加载任意 DLL 的承诺。
